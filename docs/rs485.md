# RS485 / 最小设备在线升级

## 先分清首次烧录与在线升级

RS485 只是传输接口，不会让没有接收程序的 MCU 自动具备升级能力。已有厂商 Bootloader 要按它的协议适配；不能把任意 BIN 写到 COM 口就算升级。

本项目提供**全新最小参考工程** `examples/n32g452-minimal`：N32G452 512 KiB Flash / 144 KiB SRAM，USART1 PA9/PA10，9600 8N1、地址 1、自动收发方向的 RS485 收发器。仅报告版本、进入升级、暂存新程序和切换，不包含产品业务代码，不控制未知 GPIO 输出。

首次需使用板卡确认支持的 SWD/官方 ISP 方式写入 `initial-v1.hex`，包含 Bootloader 和 1.0.0 应用。首次烧录会替换设备原程序，必须先备份、核对芯片/容量/电平/连线和恢复手段。构建脚本**不调用烧录器、不自动擦写设备**。没有兼容 Bootloader 或可用的首次烧录入口时，单凭普通 COM 连接不能完成初始化。

## 编译

安装 Keil ARMCC 5，并取得芯片官方 N32G45x 标准外设 SDK。只引用官方 CMSIS/标准驱动，不引用既有产品业务代码：

```powershell
./examples/n32g452-minimal/build.ps1 -ArmBin "C:/Toolchains/ARMCC/bin" -SdkRoot "C:/SDK/N32G45x/firmware" -OutDir "./build/n32g452"
```

输出 `boot.bin/.hex`、`app-v1.bin/.hex`、`app-v2.bin/.hex` 和首次烧录用的 `initial-v1.hex`。应用 BIN 用于后续在线更新；不要把合并 HEX 当作 BIN 发送。SDK 必须匹配 N32G45x，保留厂商许可证，参考工程不代替自己的板级适配。

## 内存与恢复策略

| 区域 | 地址 | 用途 |
|---|---|---|
| Bootloader | `0x08000000–0x08004FFF` | 升级服务，不允许应用升级覆盖 |
| 应用 | `0x08005000–0x0803FFFF` | 最大 236 KiB，新应用仍链接到此处 |
| 暂存 | `0x08040000–0x0807AFFF` | 完整接收新应用，不边收边擦当前应用 |
| 升级请求 | `0x0807F000` | 显式进入 Bootloader 的独立页 |
| 更新描述 | `0x0807F800` | SHA-256、版本、型号与待复制/已安装标志 |

完整接收并独立计算 SHA-256，核对镜像头、目标型号、版本和向量后，才保存待安装描述。Bootloader 从暂存复制到应用区，完整摘要相同才标记已安装并启动。复制期间断电，下次从保留的暂存重试，未完成时不跳转。

这是**可重试复制**，不是 A/B 回滚：复制中断后，旧应用未必还能运行；必须保持 Bootloader/暂存完整并恢复供电重试。尚未完成真实板卡的断电、欠压、写保护、Flash 寿命及看门狗验证。高可靠量产设备需另外做硬件验证和启动确认策略。

## 最简测试流程

1. 首次手动烧录 `initial-v1.hex`，正常启动后读取版本应为 1.0.0。
2. Hub 新建普通项目，公钥留空；上传 `app-v2.bin`，版本 `1.1.0`，平台 `mcu`、架构 `cortex-m4`、型号 `n32g452-demo`，然后发布。
3. Qt 示例填相同项目/适配范围，当前版本 `1.0.0`，检查并下载 BIN。
4. 展开“最小 N32G452 示例设备测试”，填端口，读取设备当前版本，再确认“将已下载 BIN 更新到设备”。工具明确写入升级请求后进入新协议，不猜未知旧协议。
5. 传输/切换后再次读取版本，应为 `1.1.0`。下载完成或收到 COMMIT ACK 均不等于已经启动成功，必须实际查询确认。

也可使用独立 Qt SerialPort 命令行工具：

```sh
firmware-hub-serial --read --port COM3 --baud 9600 --address 1 --register 17 --count 2
firmware-hub-serial --upload app-v2.bin --sha256 <下载后已核对的SHA256> --version 1.1.0 --hardware n32g452-demo --port COM3 --confirm-write --enter-boot --activate
```

示例读寄存器 17 为十进制压缩版本（100=1.0.0，110=1.1.0），18 为硬件版本 1。进入升级使用 FC06、寄存器 33、值 `0xB007`，**仅适用新示例**。`--confirm-write` 缺失时上传不发送任何命令；`--activate` 缺失时只完成暂存与校验。

## FH485/1 协议与限制

`sdk/rs485/fw485.h/.c` 使用无堆、有界状态机：单播地址、功能码 `0x41`、2 字节大端 payload 长度、command、4 字节 session、4 字节 sequence、payload、低字节在前的 Modbus CRC16。最大 payload 192 字节；DATA 为 4 字节 offset + 最多 188 字节数据。

命令：HELLO → BEGIN（大小、SHA-256、版本、型号）→ DATA → VERIFY → COMMIT。回复为 command|0x80，包含错误码、已收大小、状态和容量。重复的最后一包返回缓存 ACK，不重复写 Flash；乱序、不同内容重复包、错误 CRC/型号/容量拒绝。COMMIT ACK 物理发送完毕后才调用激活适配器。

CRC 和 SHA-256 是传输完整性，不是身份认证。本地 RS485 总线在此最小示例中被视为可信；没有设备密码学身份、Secure Boot、受保护防回滚或任意已有 Bootloader 兼容。不要将串口写权限直接暴露到公网。Qt 网关应使用受控 Hub 账号/设备凭据，网页发布权限仍需保护。

SDK 回调只给出接口；N32 示例才实现特定芯片的 Flash 适配。其他芯片必须重写 BSP、链接布局和安全启动逻辑，不能直接烧录这个二进制。
