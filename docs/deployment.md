# 部署与维护

## 参数

| 参数 | 是否需要 | 说明 |
|---|---|---|
| `USER` | 首次必填 | 初始化管理员用户名；后续不覆盖账号 |
| `PASSWORD` | 首次必填 | 12–72 字节；初始化后可移除；勿提交真实密码 |
| `TZ` | 可省略 | 默认 Asia/Shanghai |
| 端口 | 必须映射或由代理访问 | 容器固定 8080，宿主端口自由选择 |
| `/data` | 必须持久化 | 数据库、固件、服务凭据加密密钥 |

域名、代理 CIDR、设备状态和通知不需要一批额外环境变量。默认无 CORS，不支持将管理前端任意跨域嵌入。

## HTTPS 与网络

局域网浏览可使用 HTTP。生产客户端建议使用 HTTPS；Qt 示例仅允许回环地址通过 HTTP 测试。可复用 NAS/现有反向代理，不需要为本项目增加代理容器。

反向代理应保留原始 Host，设置正确 `X-Forwarded-Proto`。不依据来源 IP 自动授予权限。默认不开放额外 MQTT/CoAP 监听端口；MQTT 通知连接你配置的 Broker。

服务监听双栈环境下可用的接口；宿主 Docker、网络和反向代理也需正确启用 IPv6。具体双栈情况应以部署环境验证为准。

## NAS 权限

挂载**专用**目录，不要使用共享资料根目录。入口初始化器先检查链接/嵌套挂载，再初始化目录权限；HTTP 服务以 10001:10001 运行。不会使用 777。显式配置 `user:` 时需由部署者保证目录可写。

只读挂载、NAS ACL、root-squash、文件系统不支持 chown 不能由程序绕过。出现这些情况会明确报错，可改用 Docker 命名卷或调整专用目录 ACL。不要添加 `cap_drop: ALL` 后仍期待 root 初始化器能够 chown；如需完全降权部署，先准备目录再配置 `user: "10001:10001"`。

## 备份

```sh
docker compose exec firmware-hub firmware-hub backup
```

备份写入 `/data/backups/`，使用 SQLite 一致性快照并收集版本引用的不可变文件。包括 `master.key` 和账号/通知配置，必须将备份作为敏感文件加密保管。它不包含发布者离线私钥；发布私钥另行备份。

恢复：停止服务，将备份解压到**新的空专用数据目录**，挂载该目录再启动。不要覆盖运行中的数据库，不要从未知来源导入备份。保留原目录，验证恢复后再决定如何处置旧数据。

`master.key` 丢失会导致通知凭据无法解密；不能仅恢复数据库而丢弃匹配密钥。

## 更新

```sh
docker compose pull
docker compose up -d
```

更新前备份；优先固定发行版本标签。不是在容器内部拉代码覆盖自身，也不挂载 Docker Socket。数据库与固件留在 `/data`。

## 本地开发

Go 至少 1.26.11（安全修复版本）、Node.js 24；前端 `npm ci && npm run build` 后在项目根目录 `go run .`。`DATA_DIR` 和 `LISTEN_ADDR` 仅为开发/特殊部署选项，一般无需填写。

本地预览辅助脚本仅用于 Windows 的既有 Docker WSL 环境，运行前在脚本调用环境中选择相应发行版；它生成本地专用 Compose 和随机账号，保存在被忽略的 `.local` 中。不要将 `.local`、`data`、私钥或测试凭据提交 Git。


## 网页整站备份与异地恢复

在「系统管理 → 系统备份与恢复」下载完整 ZIP 备份包，包含账号、TOTP、项目、设备凭据、版本记录、固件文件、通知配置及 master.key。导出使用 SQLite 一致性快照，排除浏览器登录会话。包内包含解密配置所需的密钥，ZIP 本身不加密，请存放在受保护的位置。

在另一台机器部署同一项目的相同或兼容新版本，先用新部署账号登录；选择备份包，核对文件名，勾选替换确认后导入。系统先检查包类型、路径、文件校验和、数据库及密钥，再保留原数据至 `/data/previous-*`，自动重新加载服务。随后使用备份中的原账号/验证器登录；不需要手动重启或复制密钥。无效备份不会替换当前数据。单包解压内容上限 20 GB，需为上传包、展开包及原数据预留空间。

迁移的是应用数据，不含 Docker 端口、挂载目录、反向代理、TLS 证书及应用外部文件。新环境仍需能访问保存的外部服务地址，并具备对应网络权限；环境变量 USER/PASSWORD 不会覆盖恢复的账号。不要把原实例和恢复实例同时连接同一个 Telegram 机器人。恢复前请另行导出当前数据；确认恢复正常后再自行清理回退目录。

旧命令行 `backup` 生成的 ZIP 可按原来的停服解压流程恢复；网页导入使用带 MANIFEST.json 的新格式，勿混用。离线发布签名私钥不在服务端，仍需自行备份。
