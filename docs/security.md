# 安全模型与 FH1

## 保护目标与边界

默认**账号模式**依靠登录权限、可选发布密码、HTTPS、发布署名和操作日志。SHA-256 用于传输完整性，不证明发布者身份；服务器或有发布权限的账号被控制后，仍可提供恶意更新和匹配摘要。数据库日志可被服务器管理员或入侵者修改，不是不可抵赖的外部证据。

可选**高级数字签名模式**把设备最终信任根放在客户端。公钥由客户端预置；私钥不得上传到 Hub、Git、Docker 镜像或网站备份。该模式必须独立验签，失败不自动回退普通模式。`fwtool` 仅为此高级流程服务，普通发布无需使用。

只有当设备/应用正确强制高级验签、兼容检查、防回滚并保护自身信任配置时，单纯替换服务器文件才能被有效拒绝。网站被攻破仍可导致数据读取、停服、删文件或阻断更新，不能承诺绝对安全。恶意开发者或失窃签名私钥能产生有效签名；平台无法凭空判断其固件业务逻辑是否有害。

密码使用 bcrypt；设备及网页会话随机 Token 仅保存摘要；Webhook/TG/MQTT 秘密使用随机本地主密钥进行 AES-GCM 加密。主密钥在 `/data/master.key`。同一宿主被完全控制时，这种静态加密不能保护进程本来有权解密的秘密。

发布密码也使用 bcrypt，只在发布时验证；不能替代账号权限。关闭签名或变更项目发布密码要求所有者重新验证账号密码。已部署的签名客户端不会因网页设置变化自动降级。

登录历史保留最多 90 天/5000 条，包含账号、成功/失败、服务器直连地址、User-Agent 与时间。普通用户仅查看自己，管理员可查看全站并撤销会话。该日志是网页账号审计，不属于可关闭的设备心跳采集。不要依赖未验证的 X-Forwarded-For 声称获得真实终端 IP。

通知不是更新授权，不携带可远程执行的 Shell 命令。网页说明不是可信执行输入，Markdown 过滤脚本、SVG、嵌入控件和远程图片。设备状态由客户端主动上报，不通过 Hub 扫描设备，不公开设备信息。

## FH1 签名格式

外层 JSON 只有 `payload`（标准 Base64）和 `signature`（64 字节签名的十六进制编码）。签名使用标准 Ed25519，直接签署解码后的全部 payload 原始字节。

普通模式复用 FH1 的有界字段编码，但 signature 为空，由服务器生成；这不是数字签名。普通元数据默认不设短期失效（expires 使用 9999 年上限），仍按版本序号筛选。高级模式沿用发布者签署的有效期。

payload 由以下 ASCII 行组成，**每行包括最后一行都以 LF 结束**：

```text
FH1
project
version
sequence
security
channel
platform
arch
hardware
sha256
size
min_sequence
expires
```

- 标识是 1–64 个 ASCII 字符：首字符为字母或数字，后续可含 `._+-`。
- 整数使用无前导零的非负十进制，最大 int64；sequence/size/expires 必须大于零。
- SHA-256 是 64 个小写十六进制字符。
- payload 最大 1024 字节，不允许额外字段、空行、NUL 或不同换行。
- `any` 为平台/架构/型号通配；设备端仍根据本地策略验证。
- `expires` 是 UTC 秒。SDK 没有可信时间时失败关闭，不直接信任响应 server_time。
- version 是显示标识，sequence 是发布顺序，security 是安全版本下限，两者不要混用。
- min_sequence 表示必需的已安装发布序号。

服务器不依赖 JSON 重排后的内容验签，避免不同语言对序列化的理解不同。C/Go 具有互操作测试。

版本说明与下载位置不是可执行指令；文件身份由签名摘要与大小确定。下载地址必须受客户端同源/可信存储策略控制。

## 尚未具备的高保障能力

FH1 **不是完整 TUF/SUIT**。首版公钥不可在网页直接替换，轮换需通过可信客户端升级/重新预置；尚无完整根元数据轮换、多签阈值、委派角色、完整冻结攻击防护和在线撤销信任链。

过期和持久化最高序号减少旧版本回放，但不能代替完整的新鲜度体系。系统时钟回退、本地防回放状态被清除、设备无法保护状态时，保障会下降。不能仅因界面“撤回”就认为离线设备绝不安装以前下载的合法签名文件。

高风险生产设备需要结合 Secure Boot、受保护安全计数、A/B 启动确认及后续完整 TUF/平台安全 OTA 适配。参考：[TUF](https://theupdateframework.io/docs/metadata/)、[IETF RFC 9019](https://www.rfc-editor.org/rfc/rfc9019.html)、[IETF RFC 9124](https://www.rfc-editor.org/rfc/rfc9124.html)。

## 部署注意

- 管理面板公网访问必须配置 HTTPS 与强密码，建议在“账号安全”绑定 TOTP 验证器；启停需验证当前密码，更改后撤销该账号全部会话，登录校验码有重放检查。首版尚未提供 WebAuthn。
- 公开项目表示其已发布固件可被任何人下载，签名不等于保密。
- 多用户权限防止普通账号互访项目；平台管理员仍能读取服务器存储，但不能伪造独立保管的签名。
- 桌面更新器只在本机明确选择的独立目录中安装，不执行包内命令、不提权；多文件更新依靠备份和日志恢复，不宣称断电原子替换。
- RS485 是本地网关适配，不额外开放公网串口服务。最小板卡示例信任物理总线，不提供设备密钥认证、Secure Boot 或受保护防回滚，不是生产安全 OTA 方案。
- 内网 Webhook/MQTT 仅由管理员明确允许；默认拒绝私有、回环和特殊地址，连接时解析并固定目标 IP。通知不接受 HTTP 重定向。
- 不将备份、源码、私钥或原始错误堆栈暴露为静态资源。
- 只挂载专用数据目录；不要授予 Docker Socket/特权/宿主根目录权限。
